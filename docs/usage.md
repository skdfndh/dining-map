# 聚餐地图使用与发布

## 组织者编辑

编辑器地址为 `/editor.html`。默认演示密码是 `dinner`，它只用于防止误入，不是真正的权限认证。

编辑器按以下顺序使用：

1. 设置活动名称、日期、城市和简介。
2. 在左栏参与人摘要点击“编辑参与人”，集中建立名单；同名人员可增加备注，人数较多时名单在聚焦面板内滚动，不会被底部行程遮挡。
3. 通过高德搜索、地图右键选点或粘贴高德/百度链接添加地点。
4. 为地点选择精确时间、模糊时段或待定，并勾选本站参与人。
5. 使用自动排序形成初始顺序，再通过拖动或箭头调整行程。
6. 新形成的相邻地点会默认自动计算步行道路路线；如需骑行、驾车、打车或公交，点击下方两站之间的交通卡并切换方式，系统会自动重新计算。只有高德算路失败时才会显示虚线直连，此时可重试或改为自定义交通。
7. 创建站点费用或全局费用，金额可等活动结束后再填。
8. 预览手机效果并处理发布校验。
9. 导出 `event.json`，替换 `public/event.json` 后提交。

## 把观看网页发给参与者

1. 在编辑器点击“预览”，确认手机地图、路线和费用状态。
2. 点击“JSON”下载最新 `event.json`。
3. 用下载文件覆盖项目中的 `public/event.json`。
4. 将修改提交并推送到 GitHub 的 `main` 分支。
5. 在仓库 `Settings → Pages` 中确认 Source 为 `GitHub Actions`，等待 `Deploy GitHub Pages` 工作流完成。
6. 把 `https://skdfndh.github.io/dining-map/` 发给观看者；组织者编辑器地址是同一链接后的 `editor.html`，无需分享。

以后调整活动或活动后补账时，重新导出并覆盖 `public/event.json`，再次推送即可更新同一个观看链接。

新建聚餐后，先在“活动与发布”中选择省份、城市和可选区县。地图会以该行政区中心作为尚未添加地点时的初始范围；旧活动只有城市字段时仍可继续编辑。

草稿使用 IndexedDB 自动保存。点击编辑器顶部“草稿箱”可以查看这个浏览器中保存过的活动：每个活动按内部 ID 保留最新一份，最多 24 个，可恢复或删除非当前活动。恢复前会先保存当前内容；当前正在编辑的草稿不能直接删除。旧版保存的当前草稿、快照和“上个活动”也会兼容显示。导入非法或更高版本的 JSON 不会覆盖当前草稿。

“清空整个草稿箱并恢复示例”会删除此浏览器内的全部活动草稿，操作前会再次确认。草稿箱不是云端同步或备份；清除浏览器网站数据后无法恢复，重要活动仍应定期下载 JSON。

## 费用结算

金额为空表示待结算，不代表零元。支持：

- 均分；
- 按权重；
- 自定义每人金额；
- 固定部分金额后均分或按权重分配余额；
- 一笔费用由多人分别垫付。

只有全部费用金额、分摊和垫付均守恒时，才可以把结算状态标记为“已完成”。整理中状态可以发布已确认部分，但手机页会明确提示金额可能变化。

## 更换编辑器密码

在活动检查器中展开“生成新的编辑器密码摘要”，输入新密码并生成配置片段，然后替换 `src/config/editor.ts` 中的配置。密码摘要和校验逻辑都会公开，因此它不能替代服务器认证。

## 高德配置

本地使用 `.env.local`：

```text
VITE_AMAP_KEY=项目专用 Web端(JS API) Key
VITE_AMAP_SECURITY_CODE=对应安全密钥
```

GitHub Pages 使用仓库 Actions Secrets：

- `VITE_AMAP_KEY`
- `VITE_AMAP_SECURITY_CODE`

正式发布前应重新生成项目专用凭据，并把允许域名限制为 `skdfndh.github.io`。纯静态站点无法真正隐藏这些值。

## 备份与回滚

- 每次活动发布前保留一份导出的 `event.json`。
- 活动后补账时先导入最近一次发布文件。
- 需要回滚网站时，在 Git 中恢复上一版 `public/event.json` 或代码提交并重新部署。
- 参与者的“我是谁”和到达进度只保存在其手机浏览器，不包含在公共 JSON 或 CSV 中。

## 浏览器兼容说明

- 桌面编辑器优先支持当前版 Chrome、Edge 和 Firefox。
- 手机展示页面向当前版 iOS Safari、Android Chrome 和微信内置浏览器。
- 微信内可能限制地图 App 唤起或定位；此时可复制地址并在系统浏览器中打开。
