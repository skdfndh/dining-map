## Why

一次聚餐往往同时涉及多个地点、不同参与人、跨站交通和活动后的复杂 AA 结算，群聊中的零散消息难以让参与者快速理解完整安排。需要一个可长期复用、无需服务器即可部署的地图模板，让组织者在电脑上编排行程，并让参与者在手机地图中完成查看、导航、进度跟踪和结算确认。

## What Changes

- 新建一个可部署到 GitHub Pages 的纯静态多页面应用，分为桌面组织者编辑器与手机参与者展示页。
- 提供带简单密码门槛、浏览器草稿自动保存、可选择的活动草稿箱、旧活动导入、预览及 JSON/CSV 导出的桌面编辑体验。
- 支持高德搜索、地图长按、高德/百度分享链接三种地点录入方式，并提供失败后的手动选点降级流程。
- 支持精确时间、模糊时段、时间待定、跨日活动及自动初排后手动拖动的行程队列。
- 使用高德 Web 端 JavaScript API 在编辑阶段计算真实道路路线、距离与耗时，并将结果冻结到活动数据中。
- 提供地图主导的移动端展示、地点与路线详情、完整路线/逐站模式、个人到达进度以及高德/百度导航。
- 提供活动级和站点级费用、多种分摊方式、多人垫付、尾差处理、个人汇总及简化转账方案。
- 定义带版本号和稳定内部 ID 的 `event.json` 数据契约及共享校验/计算接口，支持后续模板复用。

## Capabilities

### New Capabilities

- `event-authoring`: 桌面组织者编辑器中的活动信息、参与人、地点、时间、排序、草稿、导入、预览和发布前校验。
- `itinerary-routing`: 地点录入、高德路线计算、交通方式、路线冻结、局部重算与失败降级。
- `mobile-map-experience`: 手机地图展示、站点与路线详情、逐站进度、当前站推测以及高德/百度导航。
- `expense-settlement`: 费用项目、均分/权重/自定义分摊、多人垫付、尾差、结算状态、个人账单和转账方案。
- `static-data-exchange`: 带版本号的活动数据契约、稳定 ID、浏览器本地状态兼容、JSON 导入导出及 CSV 结算导出。

### Modified Capabilities

无；当前项目没有既有 OpenSpec 能力规格。

## Impact

- 新增 Vite + TypeScript 静态前端工程、桌面编辑入口、手机展示入口及共享领域模块。
- 接入高德地图 Web 端 JavaScript API，并生成高德和百度地图导航链接。
- 新增公开的 `event.json` 数据文件、数据版本迁移边界和 CSV 导出格式。
- 引入浏览器本地存储，用于编辑器当前草稿、按活动归档的草稿箱、7 天编辑器登录状态、历史参与人备选、参与者身份选择和到达进度。
- GitHub Pages 保持唯一部署目标；不引入数据库、实时协作、服务端认证或后端密钥代理。
- 高德凭据在纯静态前端中无法保密，正式发布前必须使用项目专用凭据并限制允许域名。
