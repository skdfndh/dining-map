## Context

项目从零开始，需要同时覆盖组织者在电脑上的高密度编辑流程、参与者在手机上的地图查看流程，以及活动结束后的精确 AA 结算。部署目标仅为 GitHub Pages，因此不能依赖数据库、服务端会话、后台任务或真正保密的凭据。高德地图 Web 端 JavaScript API 负责浏览器内地图渲染、地点搜索和路线计算；百度地图仅作为导航跳转目标。

活动会经历活动前、活动中和活动后三个阶段。组织者通过导入和导出同一个带稳定 ID 的 `event.json` 推进活动状态，参与者的“我是谁”和到达进度则只保存在各自浏览器内。金额、路线和时间模型均存在多种不完整状态，系统必须将“待定”和“未填写”作为一等状态，而不是隐式转为零或错误数据。

## Goals / Non-Goals

**Goals:**

- 构建 Vite + TypeScript 多页面纯静态应用，同时提供桌面编辑器和手机地图展示页。
- 建立版本化、可校验、可复用的活动领域模型和 `event.json` 契约。
- 在编辑阶段完成高德地点选择及真实道路路线计算，并把展示所需结果冻结到活动数据中。
- 支持稳定的本地草稿、活动再导入、发布前校验和 CSV 导出。
- 使用整数金额和确定性算法完成多种分摊、多人垫付、尾差及转账计算。
- 让手机展示页在没有实时后端的情况下可靠处理逐站进度、当前站推测和双地图导航。
- 形成具有“餐桌行程地图”辨识度的暖色视觉系统，并满足基本可访问性和触控要求。

**Non-Goals:**

- 多人实时协作、数据库持久化或公共状态同步。
- 真正安全的编辑器认证、服务端授权或密钥隐藏。
- 自动将浏览器编辑结果提交回 GitHub。
- 在参与者之间同步到达状态。
- 保证第三方地图分享短链在所有情况下都可自动解析。
- 实现高德或百度原生 App 内部导航能力；本项目只负责生成和打开导航 URI/网页链接。

## Decisions

### 1. 使用 Vite + TypeScript 多页面静态架构

工程包含 `index.html` 与 `editor.html` 两个入口，并共享领域模型、校验、结算、地图适配和样式令牌。Vite 构建后生成可直接发布到 GitHub Pages 的静态资源，并配置相对基础路径以兼容项目子路径部署。

选择 TypeScript 是因为时间、站点、路线、结算状态和不完整费用均为可区分联合类型，静态类型能够阻止“空金额当作零”“模糊时段当作精确时间”等错误。相比两个独立项目，共享工程能够保证编辑预览与最终展示使用同一套渲染和领域逻辑。

### 2. 采用版本化领域数据和稳定内部 ID

`event.json` 顶层包含 `schemaVersion`、活动元数据、参与人、站点、有序站点 ID、路线段、费用项目和结算状态。参与人、站点、路线段与费用均使用不可因重新排序或再次导入而变化的唯一 ID。站点坐标以高德使用的 GCJ-02 为活动数据基准，并为导航链接生成器显式声明坐标来源。

加载器先限制输入体积并执行结构、有限数值、坐标范围和时间格式校验，再根据 `schemaVersion` 选择迁移器；未知的更高版本拒绝进入编辑状态并给出可理解错误。公开文本通过 DOM 文本节点渲染，不拼接为 HTML。领域校验分为阻断错误和警告：账目不守恒、缺少必填名称等阻止最终发布；时间冲突、路线降级和待定时间只产生警告。

### 3. 区分编辑草稿、本地查看状态和公开活动数据

- 编辑器完整草稿保存到 IndexedDB，以避免冻结路线坐标导致数据超过 localStorage 的常见容量限制。除当前自动保存草稿和滚动快照外，仓库按活动 ID 保留每个活动的最新版本，形成有界草稿箱；同一活动继续编辑只更新其条目，不生成无限版本。旧版 `current`、`snapshot` 和 `previous-event` 记录在读取草稿箱时兼容展示并按活动 ID 去重。
- 编辑器 7 天登录凭证、历史参与人目录、参与者身份选择、到达进度和最近浏览模式保存到 localStorage；活动状态仍按活动 ID 隔离，历史参与人则作为同一浏览器内跨活动复用的有界目录。读取时逐字段校验，写入失败时不阻断页面使用。
- 公开活动数据仅来自加密的 `event.enc.json`；解密得到的 `event.json` 契约和本地查看状态都不写回公开文件。

编辑器每次领域状态变更后进行防抖保存，并显示保存中、已保存或失败状态。导入活动时保留合法的稳定 ID；从历史目录加入当前活动的参与人视为新实体并生成新 ID。历史目录按规范化后的“姓名＋备注”去重，限制数量，并用中文拼音或拉丁字母生成 A–Z 索引；无可用字母的名称归入 `#`。

草稿箱显示活动名称、日期、地区、参与人/地点数量和保存时间。恢复其他草稿前先同步保存当前活动；删除只针对非当前活动并要求确认，当前活动需要先切换或新建后才能删除。损坏条目在列表和恢复时被忽略，不阻断编辑器启动。

### 4. 静态密码只作为误入门槛

独立配置保存带盐的密码派生摘要和参数，浏览器使用 Web Crypto 计算并比较摘要。内置小工具生成新配置片段，成功验证后记录一个本地 7 天会话，到期或主动退出后重新验证。

由于配置和验证逻辑均公开，此机制不宣称安全认证，仅保护编辑器入口免于误入。参与者查看密码使用独立的活动密文机制，不能与编辑器门槛混为一谈。

### 5. 高德地图能力通过适配层隔离

定义地图适配接口，分别覆盖 SDK 加载、地点搜索、地图选点、分享链接解析尝试、路线计算、覆盖物绘制和视口控制。第一版只实现高德适配器，但编辑器与展示组件不直接依赖全局 `AMap` 对象。

高德/百度分享链接解析采用“尽力而为”：先识别可直接读取的坐标、POI 或查询参数；遇到短链跨域或不支持格式时进入搜索/长按选点降级流程。解析失败不是阻断错误。

### 6. 路线在编辑时计算并冻结

每个相邻站点对产生一个路线段。步行、骑行、驾车、打车和公共交通调用对应高德路线能力；打车复用驾车路线但保留独立显示类型。路线段保存交通方式、距离、耗时、编码后的道路折线、计算时间和来源状态。

展示页只渲染冻结结果，不依赖查看时重新算路。调整队列时根据前后相邻关系比较路线段键，只使变化的路线段失效并重算；未变化的段继续复用。自定义交通或计算失败保存手动说明、手动耗时和端点，并使用虚线连接。

选择冻结路线的代价是活动当日不会反映实时路况，但它确保所有参与者看到组织者发布时确认的相同行程，也降低 API 调用和现场失败风险。

### 7. 时间采用显式联合类型和半自动排序

站点开始时间类型为精确时间、固定模糊时段或待定；结束时间可为精确时间或空。精确时间包含相对活动日期的天数，以支持跨午夜和跨日。固定模糊时段拥有稳定排序权重。

首次排序将精确时间和模糊时段按规则生成队列，待定站点留在待安排区。形成队列后手动顺序是事实来源，修改时间只更新冲突提示；只有用户显式执行“按时间重新排序”才重建顺序。

### 8. 金额统一使用整数分和确定性结算

领域层不使用浮点金额。输入层将人民币文本解析为整数分，输出层再格式化。均分和权重分配先计算基础份额，再用最大余数法按稳定参与人顺序分配余下的分，保证结果确定且总额守恒。

每笔费用分别维护承担分配和垫付记录。固定金额先扣除，余额再均分或按权重分配；自定义模式保留显式未分配金额。个人净额为承担金额减垫付金额。最终转账方案以债务人和债权人余额列表进行确定性撮合，确保每笔转账为正、所有余额归零，并避免循环转账；界面称为“简化方案”，不承诺数学意义上的全局最少转账次数。

### 9. 结算状态由组织者显式控制并受校验约束

费用金额为空使用 `null` 表示待结算，绝不自动变成零。未开始状态隐藏个人金额并显示活动后公布提示；整理中展示已确认部分和醒目非最终提示；已完成状态展示完整消费、垫付和转账。

只有全部费用有金额、每笔承担总额与垫付总额均等于费用金额、且全部个人净额合计为零时，领域层才允许进入已完成状态。草稿和整理中数据仍可导出，便于活动前后多次发布。

### 10. 手机端采用地图主导的状态机

展示页有完整路线、逐站浏览、地点详情、路线详情和费用抽屉等状态。地图标记始终显示序号、地点简称及精确时间/模糊时段/待定。已过站点通过降低亮度和混入灰色表达，不能只依赖颜色区分，仍保留序号和状态文本。

当前站优先采用用户手动到达记录，其次按本地日历日期、活动日偏移和精确开始/结束时间推测；多个精确时段重叠时选择最近开始的一站，再回退到第一个未到达站点或完整路线。用户可撤销、直接更改当前站，并在完整路线和逐站模式间往返。地图被手动拖动或缩放后，到达状态、路线选择和普通重绘不自动抢夺视口，只有显式聚焦和活动坐标变化才重设视野。

### 11. 导航链接独立于底图实现

导航生成器使用站点名称、地址和坐标分别构建高德与百度的 App/网页导航目标。点击后尝试打开相应链接；平台或微信浏览器限制无法由网页可靠检测时，界面同时提供复制地址以及“在系统浏览器打开”的指引。导航失败不影响站点详情查看。

### 12. 使用共享视觉令牌构建两种密度的界面

暖奶油、番茄红、烤橙、深酱色、低饱和灰绿组成核心色板。地点牌和底部详情卡采用“桌牌/菜单卡”意象，路线使用克制的手绘质感。移动端控制触控目标不小于 44 CSS 像素，并尊重减少动画偏好。关键控件提供可见键盘焦点；弹层具有对话框语义、可识别标题和 Escape 关闭行为；状态变化使用文本与辅助技术播报而非只改变颜色。

桌面编辑器使用三栏编排台加底部行程队列；移动展示使用全屏地图和按需出现的抽屉，不复用桌面高密度布局。两者共享排版、颜色和状态语义，而非共享相同页面结构。

参与人资源在左栏采用单行姓名签摘要，避免人数增长时与固定行程托盘争夺纵向空间。完整名单编辑使用高于行程托盘的聚焦纸卡面板，当前名单与历史备选分别拥有有界滚动区域；Escape、点击背景和关闭按钮均可退出，并将焦点返回“编辑参与人”。

发布阻断不能只复用地点搜索区的普通状态文字。导出失败后，编辑器使用置顶的暖红错误卡、资源标签角标和字段级错误边框形成三级提示；同时根据错误代码或实体 ID 切换到活动、地点、路线、参与人或费用工作区。活动名称和行政区等直接可编辑错误会自动滚动并聚焦对应控件，修复最后一项阻断错误后置顶提示自动消失。

### 13. JSON 与 CSV 都在浏览器内生成

导出器在浏览器中生成格式化 `event.json` 和带 UTF-8 BOM 的 CSV 结算表，通过 Blob 下载，不向外部服务上传活动数据。JSON 导出附带校验摘要；CSV 在整理中或已完成状态下导出已确认费用、个人承担、垫付、净额及转账信息，并明确标注是否为最终结算。

### 14. 行政区定位使用编码、级别与显式视口动作

省市区联动保存名称用于展示，并优先从仓库内置的省级、地级市中心表获得不依赖网络的近似中心；区县缺少独立中心时回退到所属城市。离线表未覆盖的新代码再使用行政区编码和对应的 `province`、`city`、`district` 级别请求高德中心点，并以底图原生 `setCity` 兜底。该独立聚焦动作优先于已有站点的全程适配，并在容器尺寸变化时保持用户刚选择的行政区视野。

### 15. 公开仓库只保存加密活动信封

编辑器仍可下载 `event.json` 作为组织者私下备份和再次导入的稳定契约，但 GitHub Pages 发布入口生成 `event.enc.json`。信封只包含版本、AES-GCM-256/PBKDF2-SHA-256 参数、随机盐、随机向量和密文，不复制活动名、日期、城市等明文元数据。PBKDF2 使用 310,000 次迭代，每次导出使用新的 16 字节盐和 12 字节随机向量。

展示页只请求 `event.enc.json`，解锁前不创建地图或显示任何活动字段。查看密码仅保留在 React 内存中，使用 Web Crypto 在浏览器本地派生密钥并解密；不上传、不写入 localStorage，刷新即丢失。文件体积、算法标识、迭代范围、盐和随机向量长度先被限制，密码错误与密文损坏使用同一条提示，避免泄露额外判断信息。

这是纯静态部署下的共享秘密，不是逐用户授权：拿到密文和密码的人可以离线解密和复制数据，也可以离线尝试猜测弱密码。因此编辑器要求至少 12 个字符，建议每次活动生成独立随机强密码并通过与页面链接分开的渠道发送。发布真实明文后切换到此方案时，需要重写 Git 历史并删除旧 Pages 构建记录；仍无法撤回他人已保存的克隆、缓存或截图。

## Risks / Trade-offs

- [高德 Key 和安全密钥在静态前端中公开] → 使用项目专用 Web 端凭据、限制 GitHub Pages 域名、上线前轮换；未来需要更强保护时再引入代理。
- [简单密码可被绕过] → 界面明确其仅防误入，不在活动数据中存放敏感信息，也不将其当作授权边界。
- [公开密文可被离线破解或由持有密码者转存] → 强制密码最低长度、使用高成本 PBKDF2 和随机盐，为每次活动使用独立强密码，并明确其是共享秘密而非账号权限。
- [地图分享短链可能因跨域无法解析] → 提供搜索和长按选点的明确降级路径，并保留原链接供人工核对。
- [冻结路线不能反映实时路况] → 显示路线计算时间，允许组织者发布前主动重算，导航按钮仍由地图 App 提供当时路线。
- [公共交通算路依赖城市和服务可用性] → 缺少城市时警告；计算失败允许改为自定义交通并发布。
- [活动 JSON 或本地草稿损坏] → 导入时先做结构校验和版本检查，自动保存保留最近可用快照，并允许用户手动下载备份。
- [超大或恶意构造的活动 JSON 消耗资源或注入标记] → 限制文件体积、收紧数值边界，并始终以文本节点呈现活动字段。
- [站点标签密集时遮挡] → 根据缩放级别控制次要文字、保持序号可见，并提供逐站聚焦与完整路线重置。
- [本地状态在清除浏览器数据后丢失] → 将其定位为个人便利状态，不作为活动事实；展示页始终可以重新选择身份和当前站。
- [简化转账不是全局最少次数] → 保证守恒、确定、无循环并在界面使用“简化方案”表述。
- [微信内导航唤起不稳定] → 保证基础地图和详情可看，并提供系统浏览器指引与地址复制。

## Migration Plan

1. 建立静态工程、共享领域模型和示例 `event.json`。
2. 实现编辑器基础数据流、草稿、导入导出与校验。
3. 接入高德地图和冻结路线，并完成桌面行程编排。
4. 实现手机展示、个人本地状态及双地图导航。
5. 实现费用算法、费用界面和 CSV 导出。
6. 使用示例活动完成桌面与手机端验收，再构建 GitHub Pages 产物。
7. 发布前轮换高德项目凭据并配置允许域名；上传构建产物及活动 JSON。

回滚时保留上一版静态构建产物和 `event.json`，直接恢复对应文件即可。数据版本升级必须保留向旧版本读取的迁移器，或在不兼容时提供清晰拒绝信息。

## Open Questions

- 首次实现时需要通过高德当前 SDK 实测确认各交通插件的返回折线格式和 GitHub Pages 域名白名单配置细节。
- 高德和百度最新导航 URI 在 iOS、Android、微信及普通浏览器中的行为需要建立设备验收矩阵。
- 站点数量达到何种规模后需要启用标签聚合或更激进的信息隐藏，可在真实活动数据测试后确定阈值。
